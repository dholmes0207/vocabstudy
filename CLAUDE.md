# Quy tắc cho trợ lý AI trong repo này

Áp dụng cho mọi phiên Claude Code (hay trợ lý AI khác) làm việc trên repo, kể cả khi người
khác clone về. Các quy tắc ở đây được ưu tiên hơn mặc định của công cụ.

## 1. Không để lại dấu vết AI

Repo này không ghi công cho Claude hay bất kỳ công cụ AI nào.

- **Commit**
  - Không thêm `Co-Authored-By: Claude …`, `Claude-Session: …` hay bất kỳ dòng ghi công, link
    phiên làm việc nào vào commit message.
  - Commit đứng tên người đang làm việc (`git config user.name` / `user.email` của họ). Nếu
    danh tính đang là `Claude <noreply@anthropic.com>` hoặc chưa đặt, dừng lại và hỏi người
    dùng danh tính đúng trước khi commit.
- **Nhánh**: tên nhánh không bắt đầu bằng `claude/` và không chứa chữ `claude`. Dùng tiền tố
  theo loại việc: `feat/…`, `fix/…`, `chore/…`, `docs/…`. Nếu môi trường giao sẵn một nhánh
  `claude/…`, hỏi người dùng nên đẩy lên nhánh nào.
- **Pull request, review, bình luận trên GitHub**: không thêm "🤖 Generated with Claude Code",
  "Generated by Claude Code", link `claude.ai/code/session_…` hay chữ ký tương tự. Mô tả PR
  theo `.github/pull_request_template.md`.
- **File trong repo**: không commit thư mục `.claude/` (đã có trong `.gitignore`), báo cáo
  phiên làm việc của AI, ghi chú cài công cụ AI (MCP, skill, `~/.claude*`), hay nhắc tới
  Claude/Anthropic trong code, comment, tài liệu. File `CLAUDE.md` này là ngoại lệ duy nhất.

## 2. Giữ cấu trúc repo gọn

- **Tài liệu** nằm trong `docs/`: `DEPLOY.md`, `PLAN.md`, `design/` (thiết kế từng tính
  năng), `research/` (quan sát web khác), `sources/` (tài liệu gốc). Ở thư mục gốc chỉ có
  `README.md` và `CLAUDE.md`.
- **Cấu hình**: Vite, Vitest, PostCSS và Tailwind dùng chung `vite.config.ts`; Prettier nằm
  trong khoá `prettier` của `package.json`. `tsconfig.json` ở gốc chỉ trỏ tới
  `src/tsconfig.json` (app, kèm `vite.config.ts`) và `functions/tsconfig.json` (Workers). Không
  tạo file cấu hình mới ở thư mục gốc khi file sẵn có chứa được.
- **Code**
  - `src/lib/`: logic thuần, test đặt cạnh file (`*.test.ts`).
  - `src/store/`, `src/hooks/`, `src/components/`: store Zustand, hook, UI dùng chung.
  - `src/features/<tính năng>/`: từng màn hình.
  - `functions/api/`: API (Cloudflare Pages Functions).
  - `public/data/`, `public/audio/`: dữ liệu và audio sinh sẵn.
  - `scripts/`: script dựng dữ liệu. `supabase/`: schema, mẫu email.
- Không để file tạm, file nháp, code chết hay sản phẩm build trong repo.

## 3. Trước khi commit

Chạy giống CI (`.github/workflows/ci.yml`), chỉ commit khi tất cả đều qua:

```bash
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
```

## 4. Commit message

- Viết tiếng Việt, dạng `loại(phạm vi): mô tả`. Ví dụ: `feat(đọc truyện): …`,
  `fix(ôn tập): …`, `chore: …`, `docs: …`.
- Thân commit (nếu cần) gạch đầu dòng: thay đổi gì và vì sao.
- Không có dòng ghi công (xem mục 1).
